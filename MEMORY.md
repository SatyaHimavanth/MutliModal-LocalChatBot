# Project Memory

Keep accepted decisions and verified findings here. Mark proposals and unverified behavior clearly.

## Goal and accepted architecture

- Build a local-first multimodal RAG chatbot/agent for organizational employees. First release targets Windows 11 x64 CPU; macOS is planned.
- IT distributes the application, llama.cpp runtime, and models. Users launch the app executable; batch files are developer helpers only.
- Tauri owns the desktop shell and process supervision. Rust/`langchain-rust` owns production text/image agent orchestration and tool events, SQLite-backed agent memory, extraction, chunking, and embedding/retrieval calls. The default-off `mcp-demo` feature adds experimental Streamable HTTP connectors; it is not authorized for organizational use.
- One llama.cpp model router runs at `127.0.0.1:8080`: `llama-server --models-dir ./models --host 127.0.0.1 --port 8080 --models-max 2`. Tauri loads both configured models at startup and owns five-minute idle unloading so active UI and long imports can hold models awake.
- SQLite/SQLCipher, `sqlite-vec`, and SQLite FTS5 are used for encrypted local history/state, semantic search, and BM25 keyword search. Embeddings are generated by the model endpoint.
- Protect a random database key using OS credential storage (Windows user-scoped DPAPI first, macOS Keychain later). Do not use a MAC address as a secret. No recovery unless policy requires it.

## Product behavior and resource limits

- Available app memory may be 2–5 GB, sometimes 2–3 GB. Idle model offload/sleep is required. 32k/64k/128k are context candidates, not guaranteed safe profiles; select conservatively using live available memory and measured costs.
- Benchmark `-b`/`-ub` with fixed hardware, model, prompt, warm-up, throughput, peak RAM/VRAM, and failures. User reports 2–3 GB VRAM for two models at 64k/default `-b`/`-ub`; prompt processing speed needs investigation.
- v1 formats: PDF, DOCX, XLSX, CSV, PPTX, common images, and supported audio. Audio is cross-modal retrieval only; no transcription model. Video deferred.
- Exact duplicate detection uses streaming SHA-256. Keep source paths, content identity, and collection membership separate. Reuse cached extraction/chunks/vectors only when ingestion fingerprints match. Extracted-text hashes may suggest candidates but do not prove multimodal equivalence.
- Collections are employee-local filters. New chats default to all; user can choose zero/one/many/all. Mid-chat changes affect future turns only and warn about context changes.
- Editing a prior input forks a timeline. It inherits the collection selection at the fork point unless the user changes it during editing. Preserve previous branches, answers, and citations.
- Show sources, connector progress, token counts, elapsed time, speeds, and branch position. Assistant responses stream into the UI and render safe Markdown. MCP tool inputs/results are withheld from chat. Input/output metrics use hover descriptions. UI reference interpretation: `docs/ui-reference.md`.
- Chat paperclip adds text-bearing files to the user turn only. Extracted text is encrypted with that message for timeline continuity, capped at ~5,000 estimated tokens, and can be explicitly imported into selected collection(s) after the response. Supported images/audio are also sent to the chat model and displayed in the assistant's expandable Sources section. Precise visual identification is not reliable in the current local QA; see `docs/chat-image-qa.md`.

## Verified llama.cpp findings

- Local Windows x64 `llama-server.exe --version`: `1.0.0-dev (build 12359, commit b1b770d90)`.
- `qa/test_embedding_modalities.py` passed text, PNG, and WAV `/v1/embeddings` inputs with EmbeddingGemma-2 Q8_0 plus projector; each produced a finite, unit-normalized 768-dimensional vector. It did not test video or retrieval quality. Audio fixture was a synthetic tone.
- Image embedding worked with `-b 2048 -ub 2048`; `-ub 64` failed model initialization due to projector minimum image-pixel constraints. This is a memory-fit risk, not a production recommendation.
- The router invocation with the current model folders and sidecars is still unverified end-to-end. `models/start-servers.bat` is a developer helper; the app starts its own router.
- Router startup now passes tracked `models/app-models.ini`, which enables embedding mode and mean pooling for `EmbeddingGemma-2`; this addresses the observed router `/v1/embeddings` HTTP 501 configuration. Successful runtime embedding through this preset is still unverified.
- Tauri's default window capability explicitly grants `core:event:default` so the frontend may register streamed chat and file-drop event listeners.
- FFmpeg/FFprobe are absent from the checked release archive, so video stays out of v1.
- 2026-11-15 image-chat smoke check used the running b12359 router and LFM3-Omni 2B Q4_K_M with `mmproj-LFM3-Omni-2B-Q8_0.gguf`. The original `qa/chess-puzzle.jpg` was accepted as a base64 JPEG image part, but the model invented multiple pieces/squares and returned malformed FEN in 13.9 seconds. Treat precise image reasoning as unreliable; see `docs/chat-image-qa.md`.
- On 2026-11-15, a generated 60-second MP3 sent whole to the live b12359 router `/v1/embeddings` failed with HTTP 500: `input (1504 tokens) is too large to process ... current batch size: 512`. The earlier QA covered only a one-second WAV. Collection audio is now decoded with Symphonia, converted to 16 kHz mono, and split into eight-second windows with one-second overlap. The 60-second fixture yielded nine WAV requests, all accepted by the router with finite 768-dimensional vectors; no `-ub` change was made. This proves endpoint acceptance for a tone, not speech retrieval quality.

## Current implementation state

- Initial Tauri 2/Rust app exists in `src-tauri/`; static chat UI is in `ui/`.
- App attempts to launch the provisioned llama.cpp router at startup, keeps the UI open with an actionable status if startup fails, and stops the child on app exit.
- UI provides a chat surface, all/none/subset collection picker that closes on outside click, a separate collection management page with create/rename/delete/import actions, native file drop and Windows multi-file picker, severity-colored notices, model idle-state warning, streamed assistant text with safe Markdown rendering, hover-described token and timing metrics, a saved conversation sidebar, expandable source excerpts, and Edit with an in-chat timeline switcher. Sidebar actions include pin, rename, archive/restore, and delete. Collection changes mid-chat warn that they affect future turns only.
- Windows initializes SQLCipher history in the Tauri app data folder, protects a random 256-bit database key with user-scoped DPAPI, and persists/reopens chats. It refuses to silently recreate an existing database when the protected key is missing. macOS keychain storage is not implemented yet.
- Import supports PDF, DOCX, XLSX, PPTX, CSV, TXT, Markdown, PNG/JPEG/BMP/GIF/TGA, and WAV/MP3/FLAC. Media is capped at 8 MB and stored as encrypted database blobs; text-bearing imports retain extracted text. It streams SHA-256 for exact duplicate detection and stores paths and collection memberships separately. PDF image-only/scanned documents need OCR and currently report no extractable text. WebP remains unsupported because the pinned llama.cpp build does not document its decoder. See `docs/ingestion.md`.
- Text-bearing documents are split into 900-character chunks with 120-character overlap, embedded in batches of up to four through `/v1/embeddings`, and stored in SQLCipher via sqlite-vec. FTS5 indexes chunk text and filenames. Hybrid search fuses up to 160 vector and 60 BM25 candidates with reciprocal rank fusion, deduplicates them, and caps the context at six excerpts. User-turn collection selection and assistant source excerpts are persisted. Retrieval candidates are filtered to selected collection memberships before prompt assembly; source text is marked as untrusted. This implementation has not yet been runtime validated. See `docs/retrieval.md`.
- Editing a prior user message forks a persisted timeline within the same root conversation. The sidebar lists each root chat once; a timeline switcher navigates saved variants. Conversation management includes pin, rename, archive/restore, and deleting the full timeline tree.
- Image/audio imports and typed embedding requests are implemented. Image indexing may fail because endpoint QA required `-ub 2048`, intentionally not enabled under the constrained memory budget. Audio collection indexing decodes locally and splits recordings into overlapping segments; see the verified follow-up below. Streamed chat, Markdown, workplace prompt, direct image/audio chat input, collection extracted-content viewer, and responsive media previews are implemented but not GUI/runtime verified. Production `langchain-rust` agent execution and encrypted SQLite memory are implemented for text/image turns; durable mid-run checkpoints, resource-aware context selection, installer validation, and full retrieval/timeline validation remain. Retrieval searches up to 160 global vector candidates and fuses those with selected-collection BM25 results. Text batches of up to four and packaged-router retrieval have not been runtime verified.
- Dependencies include Tauri 2, `langchain-rust 8`, `rusqlite 0.38` with SQLCipher, `sqlite-vec 0.1.9`, `pdf-extract 0.12.1`, `calamine 0.36.1`, `csv 1.4.0`, `quick-xml 0.41.0`, `zip 8.6.0`, and SHA-256 support. Windows `cargo check --offline` passes. This is compile verification only, not GUI/runtime/packaging verification.
- `.gitignore` excludes model/vendor binaries, generated QA artifacts, local data, and build output while retaining QA source and developer docs.
- Collection details list files, sizes, chunk indexing status, and source paths. Removing a collection's file membership also removes its chunks/vectors only when no other collection references that document.
- Chat page collection selection is positioned in the header; collection cards use a responsive grid. Prompt token count, first-token latency, and prompt throughput display below user turns with accessible dark tooltips. Timeline navigation is rendered under the edited user turn.
- Collection imports emit per-file extraction and per-document embedding progress to the Collections page, including the selected collection, filename, chunks, and an approximate ETA; active collection cards show a spinner. Chat shows a short staggered thinking animation until the first streamed token. Both respect reduced-motion settings. This UI behavior is compile/syntax checked but not runtime validated.
- Document vector indexing now isolates each document. An embedding or vector-save failure removes that document from the destination collection and removes its cached content/chunks/vectors if no other collection references it; remaining documents continue indexing. Per-file extraction/indexing status, errors, and one-time in-place retry are displayed. The status cannot close while processing, auto-clears eight seconds only when all files succeed, and remains until manually dismissed after partial/failure outcomes (with a warning). Audio segmentation passed a synthetic-fixture endpoint test; the complete collections UI import/retry flow has not been runtime validated.
- Pending chat turns show thinking and current tool activity without an ETA. Completed turns continue to display input/output token counts, elapsed time, and processing/generation speed.
- Chat turns are persisted with a pending assistant row before retrieval and generation. While a stream is active, its text buffer remains available in the UI across conversation switches, the sidebar marks its root chat with a spinner, and Stop cancels the HTTP stream. Stopping saves any partial response followed by “User interrupted generation.” Pending rows left by an app exit are marked interrupted on next startup. This lifecycle is compile-checked but not GUI/runtime verified.
- Retrieval supplies sqlite-vec's `k = ?` KNN constraint for a 160-candidate vector search; the earlier `LIMIT` form triggered the user's reported missing `k` constraint error. FTS5 keyword results are fused with vector results and both are capped to six final sources.
- The UI no longer displays “Local model service is ready” in the chat header. Tauri starts both configured models, tracks UI activity and active chat/import work, then unloads both through the router after five idle minutes. An explicitly unloaded model uses `/models/load`; a still-running sleeping model is woken with a minimal inference request because b12359 returns HTTP 400 (“model is already running”) for `/models/load` in that state. This updated lifecycle and startup model warmup compile but have not been runtime validated. Opening a recent chat exits Collections; archived conversations are read-only until restored, enforced in both UI and `send_message`.
- Message toolbars provide copy, edit, delete-turn, and response regeneration actions. Deleting a user turn removes it and later messages from that selected timeline; removing an assistant response removes it and later messages while retaining the user prompt. The selected timeline ID stays the same, and sibling edited timelines remain unchanged. Message rows are hidden for this timeline rather than physically erased because they may be shared by another branch. The edit composer has a Cancel action. This behavior is compile-checked but not runtime verified.
- On 2026-11-14, the user's explicit fresh-start request removed `conversations.sqlite3`, its `-wal`/`-shm` sidecars, and `database-key.dpapi` from `%APPDATA%\\com.organization.multimodal-local-chatbot`. The app did not initialize new storage because Windows WebView2 failed to create the window (`0x800700AA`, then `0x8000FFFF`); preserve this limitation when reporting runtime status.
- The collection target dialog is a searchable multi-select with a scrollable four-row results list, Enter-to-add, removable chips, and two-Backspace chip removal. Copying an assistant response includes sources under a `Sources` heading only while its source disclosure is expanded. These frontend changes were syntax-checked but not visually runtime-tested.
- Production text/image chat uses `langchain-rust`'s `AgentExecutor` with encrypted SQLite `BaseMemory`, transcript reconciliation, and a 20-message context window that preserves complete tool turns. Every text/image agent turn includes `get_current_datetime`, returning the computer's local date, time, weekday, and UTC offset. The prompt requires it before calendar MCP calls for unspecified or relative dates and directs the agent to pass its local date rather than trust the server's implicit “today.” Selected collections expose a local search tool; retrieval runs only when invoked and returned sources are persisted for the assistant message. Agent tool schemas are capped at 15 per turn, including the built-in date/time tool and local search. OpenAI-compatible stream usage is enabled so input/output token totals aggregate across model calls. Tool invocation metadata (tool/connector names, status, elapsed time, and safe summaries) is persisted with the assistant message and restored when the conversation is reopened; raw arguments and results are excluded. The UI shows the current tool step and a collapsible chronological log that auto-collapses when final text begins. Audio-bearing histories keep the direct streaming path. The default-off `mcp-demo` feature exposes custom Streamable HTTP connectors, encrypted custom headers, availability checks every ten minutes while the model is loaded, per-conversation selection, and user notifications/selection clearing on connector failure. Default and feature-enabled Rust tests pass; full Tauri/WebView and live local collection retrieval remain unverified. The local FastMCP Calendar demo was checked in-process and over Streamable HTTP with FastMCP's client; Rust-app interoperability is still unverified. Memory is saved after successful turns and is not a resumable mid-run checkpointer. See `docs/agent-and-mcp.md`.
- The agent prompt explicitly names `search_local_documents` and requires calling it after relevant MCP tools when local search is available; pretrained-knowledge fallback must carry an explicit unverified-knowledge label. Output throughput uses the interval between the first and last observed response chunks and is omitted when that interval is unavailable or under 10 ms. Pending user messages retain copy but hide edit/delete. The composer blocks a second submission while status/model loading is underway, and the database rejects starting another turn while an assistant response is pending. Model wake/load is serialized, and the send path ensures the chat model is awake before inference. Tool logs render above the answer. Prompt-order, pending-turn guard, and output-speed tests pass; full Tauri/WebView behavior still needs verification.
